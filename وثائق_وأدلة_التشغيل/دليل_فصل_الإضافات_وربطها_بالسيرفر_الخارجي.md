# 🧩 دليل فصل الإضافات (داعم بلس / وحدة بلدي) وربطها بالسيرفر الخارجي

تم فصل **عنوان السيرفر** عن كود الإضافات بالكامل، فأصبح لكل إضافة ملف إعدادات واحد (`config.js`) وصفحة إعدادات داخلية، بحيث يمكن مستقبلاً ربط الإضافة بالسيرفر الخارجي (الشبكة الداخلية / VPN) **من واجهة الإضافة فقط** دون تعديل أي كود أو إعادة تحزيم.

---

## 🗂️ 1. البنية الجديدة (في كل إضافة)

| الملف | الوظيفة |
| --- | --- |
| `config.js` | **نقطة الفصل الوحيدة** — عنوان السيرفر وقراءته وحفظه وبناء روابط الواجهات |
| `options.html` / `options.js` | صفحة إعدادات السيرفر (حفظ / اختبار اتصال / العودة للافتراضي) |
| `background.js` | يستخدم `config.js` لبناء روابط الطلبات — بلا أي عنوان ثابت |
| `popup.js` | يبني رابط النافذة المنبثقة من السيرفر المُعد حالياً |
| `content.js` | يتعرّف على صفحات لوحة التحكم عبر `DaemConfig` لا عبر اسم نطاق ثابت |

> 🔎 لم يعد هناك أي عنوان سيرفر مكتوب داخل ملفات المنطق — العنوان الافتراضي موجود في `config.js` فقط.

---

## ⚙️ 2. واجهة الإعدادات (`DaemConfig`)

| الدالة | الوصف |
| --- | --- |
| `DaemConfig.getServerUrl()` | عنوان السيرفر الحالي (Promise) |
| `DaemConfig.apiUrl('/api/leaves')` | بناء رابط واجهة برمجية كامل |
| `DaemConfig.setServerUrl(url)` | حفظ سيرفر جديد (فارغ = العودة للافتراضي) |
| `DaemConfig.isDashboardUrl(href)` | هل الصفحة الحالية تخص لوحة التحكم؟ |
| `DaemConfig.isDashboardPath(href, ['/new'])` | فحص المسار داخل لوحة التحكم |
| `DaemConfig.hostPattern(url)` | نمط الصلاحية المطلوب لهذا السيرفر |

يُحفظ العنوان في `chrome.storage.local` تحت المفتاح `daemServerUrl`، وأي تغيير ينعكس فوراً على كل أجزاء الإضافة دون إعادة تشغيلها.

---

## 🔗 3. ربط الإضافة بالسيرفر الخارجي (خطوات المستخدم)

1. الضغط على **⚙ إعدادات السيرفر** أعلى نافذة الإضافة (أو زر يمين على أيقونة الإضافة ← «خيارات»).
2. كتابة عنوان السيرفر الخارجي، مثال:
   ```text
   http://192.168.1.100:3000
   ```
3. الضغط على **🔌 اختبار الاتصال** للتأكد من الوصول.
4. الضغط على **💾 حفظ** ثم الموافقة على طلب صلاحية الوصول للعنوان الجديد.
5. للعودة للسحابة: **↩️ العودة للافتراضي**.

> ✅ لا حاجة لأي تعديل برمجي ولا لإعادة تثبيت الإضافة.

---

## 🔐 4. الصلاحيات

* الصلاحية الثابتة في `manifest.json` بقيت للسيرفر السحابي الافتراضي فقط.
* أي سيرفر خارجي يُمنح صلاحيته **عند الطلب** عبر `optional_host_permissions` وموافقة المستخدم — وهو الأسلوب الآمن المعتمد في Manifest V3.
* في إضافة «وحدة بلدي» يقوم `background.js` بتسجيل سكربت الحقن (`vercel-inject.js`) على السيرفر الخارجي ديناميكياً بعد منح الصلاحية، ويُلغي التسجيل تلقائياً عند تغيير السيرفر.

---

## 🧪 5. التحقق بعد الربط

| العنصر | النتيجة المتوقعة |
| --- | --- |
| نافذة الإضافة | تفتح صفحة السيرفر الخارجي (`/extension-popup` أو `/whatsapp-popup`) |
| زر «اختبار الاتصال» | ✅ الاتصال ناجح |
| إنشاء بلاغ من منصة داعم | يُسجَّل في قاعدة بيانات السيرفر الخارجي |

عند فشل الاتصال تظهر رسالة واضحة في صفحة الإعدادات دون توقف بقية وظائف الإضافة.

---

## 📌 6. ملاحظات

* رقم إصدار كل إضافة لم يُغيَّر حتى لا يتأثر تنبيه التحديث المرتبط بالموقع — يُرفع الإصدار عند توزيع نسخة جديدة على الموظفين.
* الملف المضغوط القديم في مجلد `الإضافات` لم يُحدَّث؛ يُعاد ضغط المجلدات عند التوزيع.
* السيرفر الخارجي يجب أن يسمح بطلبات الإضافة (CORS) على مسارات `/api/*` كما هو الحال في السيرفر السحابي.
