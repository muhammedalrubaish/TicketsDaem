# دليل الأمان والعزل الكامل لشبكة الأمانة ومودم العمل الداخلي

تم ضبط إعدادات المشروع لتكون **سرية ومعزولة بنسبة 100%** ولا يمكن الوصول إليها إلا لمن هو متصل بمودم الأمانة الداخلي أو عبر شبكة العمل الخاصة.

---

## 🔒 1. كيف نضمن سرية البيانات وعزلها بالكامل؟

1. **الربط على IP المودم الداخلي (LAN Binding):**
   * عند تشغيل السيرفر في بيئة العمل، يتم ربط الموقع بـ IP الشبكة الداخلية (مثال: `http://192.168.1.50:3000` أو `http://10.x.x.x`).
   * **النتيجة:** أي شخص خارج مودم الأمانة لن يفتح معه الرابط نهائياً حتى لو عرف العنوان.

2. **عزل قاعدة البيانات في السيرفر المحلي (On-Premises):**
   * قاعدة البيانات (PostgreSQL) ستعمل داخل السيرفر نفسه دون أي اتصال خارجي أو سحابي.
   * لا تخرج أي بيانات أو بلاغات خارج مبنى الأمانة.

3. **حماية ملفات وبيانات تسجيل الدخول:**
   * تم استبعاد ملفات كلمات المرور والبيانات الحساسة من الرفع العام (عبر `.gitignore`).
   * إمكانية تفعيل تسجيل الدخول بكلمات مرور مشفرة وصلاحيات للموظفين فقط.

4. **إغلاق الوصول عن محركات البحث تماماً:**
   * ملفات الروبوت ووسوم الميتا مضبوطة على `noindex, nofollow, noarchive`.

---

## 💻 2. خطوات تشغيل السيرفر داخل شبكة ومودم الأمانة:

1. **توصيل السيرفر بالمودم الداخلي للأمانة** (عبر كابل إيثرنت أو واي فاي المودم المعتمد).
2. **معرفة IP السيرفر الداخلي:**
   * في سيرفر Ubuntu ننفذ: `ip a` أو `hostname -I` (مثلاً: `192.168.1.70`).
3. **تشغيل النظام:**
   ```bash
   docker-compose up -d --build
   ```
4. **توزيع الرابط الداخلي على الموظفين:**
   * يفتح الموظف جهازه المتصل بنفس المودم ويدخل إلى المتصفح:
     `http://192.168.1.70:3000`
