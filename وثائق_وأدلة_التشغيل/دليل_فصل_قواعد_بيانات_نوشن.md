# 📊 دليل فصل قواعد بيانات نوشن وإضافة قواعد جديدة على السيرفر الخارجي

تم فصل كل ما يخص **نوشن (Notion)** في وحدة مستقلة، بحيث تصبح إضافة أي قاعدة بيانات نوشن جديدة مستقبلاً **عبر متغيرات البيئة فقط** — دون أي تعديل على الكود أو إعادة برمجة.

---

## 🗂️ 1. البنية الجديدة

| الملف | الوظيفة |
| --- | --- |
| `lib/notion/config.ts` | سجل قواعد بيانات نوشن (يُقرأ من متغيرات البيئة) |
| `lib/notion/client.ts` | عميل الاتصال بنوشن (يدعم توكن لكل قاعدة + عنوان واجهة بديل) |
| `lib/notion/sync.ts` | منطق الإنشاء والتحديث والمزامنة مع Supabase |
| `lib/notion/index.ts` | نقطة الدخول الموحّدة |
| `lib/notionSync.ts` | ملف توافق فقط (يعيد التصدير) لعدم كسر الاستيرادات القديمة |
| `app/api/notion-databases` | واجهة فحص للتأكد من القواعد المعرَّفة على السيرفر |

> 🔎 لا يوجد أي معرّف قاعدة بيانات مكتوب داخل الكود بعد اليوم.

---

## ⚙️ 2. متغيرات البيئة

| المتغير | الوصف |
| --- | --- |
| `NOTION_SECRET` | توكن نوشن العام (إلزامي) |
| `NOTION_DATABASE_ID` | قاعدة توزيع البلاغات (يُحدَّث فيها حقل «الحل المقترح») |
| `NOTION_STATUS_DATABASE_ID` | قاعدة حالات البلاغات (تُنشأ فيها البلاغات ويُحدَّث فيها «الحالة» و«Due Date») |
| `NOTION_DATABASE_ENABLED` | تعطيل/تفعيل قاعدة التوزيع (`true` افتراضياً) |
| `NOTION_STATUS_DATABASE_ENABLED` | تعطيل/تفعيل قاعدة الحالات (`true` افتراضياً) |
| `NOTION_EXTRA_DATABASES` | **قواعد إضافية بصيغة JSON** (هنا تُضاف أي قاعدة جديدة) |
| `NOTION_API_BASE_URL` | عنوان بديل لواجهة نوشن عند استخدام وسيط/سيرفر خارجي (اختياري) |

---

## ➕ 3. إضافة قاعدة بيانات نوشن جديدة (على السيرفر الخارجي)

بعد استيراد قاعدة البيانات في نوشن ومشاركتها مع التكامل (Integration)، يكفي إضافة سطر واحد في ملف `.env` على السيرفر:

```bash
NOTION_EXTRA_DATABASES='[
  {
    "key": "archive",
    "label": "أرشيف البلاغات",
    "databaseId": "xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx",
    "role": "status",
    "syncToSupabase": true,
    "canCreate": false
  }
]'
```

ثم إعادة تشغيل الحاوية:

```bash
docker-compose up -d --build
```

### 🧩 الحقول المتاحة لكل قاعدة

| الحقل | الافتراضي | الوصف |
| --- | --- | --- |
| `key` | (إلزامي) | معرّف داخلي مختصر وفريد |
| `databaseId` | (إلزامي) | معرّف القاعدة في نوشن |
| `label` | = `key` | اسم للعرض في السجلات |
| `role` | `custom` | `distribution` أو `status` أو `custom` |
| `enabled` | `true` | تفعيل/تعطيل |
| `secret` | توكن عام | توكن خاص بهذه القاعدة إن اختلف |
| `canCreate` | `false` | هل تُنشأ فيها البلاغات الجديدة؟ |
| `syncToSupabase` | `true` | هل تُقرأ تعديلاتها وتُحدَّث في قاعدة البيانات؟ |
| `useFallbackValues` | `false` | مزامنة المستقبل/التصنيف/تاريخ الاستقبال مع قيم افتراضية |
| `postJournalComments` | `false` | إضافة تحديثات دفتر اليومية كتعليقات |
| `properties` | الأسماء المعتمدة | تخصيص أسماء الأعمدة إن اختلفت |

### 🏷️ تخصيص أسماء الأعمدة

إن كانت القاعدة المستوردة تستخدم أسماء أعمدة مختلفة:

```json
{
  "key": "excavations",
  "label": "بلاغات الحفريات",
  "databaseId": "xxxxxxxx",
  "properties": {
    "title": "رقم البلاغ",
    "solution": "حالة المعالجة",
    "dueDate": "تاريخ الاستحقاق",
    "receiver": "الموظف المستقبل",
    "category": "التصنيف",
    "reason": "وصف البلاغ",
    "phone": "جوال المستفيد",
    "municipality": "البلدية"
  }
}
```

> ⚠️ أي خاصية لا تُذكر تأخذ الاسم الافتراضي المعتمد في قواعد وحدة بلدي.

---

## ✅ 4. التحقق بعد الإضافة

من داخل السيرفر أو المتصفح:

```bash
curl http://<SERVER_IP>:3000/api/notion-databases
```

النتيجة تعرض عدد القواعد المفعّلة وأدوارها (مع إخفاء معظم المعرّف لأسباب أمنية).

---

## 🔒 5. ملاحظات أمنية

* لا تُرفع التوكنات أو معرّفات القواعد إلى Git إطلاقاً — تُوضع في `.env` على السيرفر فقط.
* واجهة `/api/notion-databases` لا تُظهر التوكنات ولا المعرّف الكامل.
* كل عمليات نوشن محاطة بمعالجة أخطاء صارمة: فشل أي قاعدة لا يوقف باقي القواعد ولا الخدمة.
